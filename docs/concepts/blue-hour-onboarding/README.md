Implies the interview leg runs on Muse, not the Claude-CLI intake leg. Rejected: catalogue pick (weaker reveal); Muse-authored world (validator 2+ portals / 8+ traps -> fragile).
- Meta scope in onboarding -> **all four**: SAM witness on the card, Llama diversion drill, Muse reads a screenshot to pre-fill, real tokens + est. $ on the register.
Wave 2 (2026-10-20):

Director decisions (convention or judgement, overridable):
- Hero demo: persona mira (README:91 freelancer), chore = `freelancer-receivables` (chase overdue invoices; gated send_reminder). The video films this path; any user may define any chore.

## Design brief

### Summary
A non-developer installs Athena and, in one sitting, connects Meta's Muse with a guided key paste, shows Athena one of their apps and answers a few rounds of suggested questions while their Blue Hour rail draws itself in front of them. Athena maps the answers to one of 100 validated chores, opens a sandbox copy of that app in a real tab, and runs one live Muse turn that stops at the red signal with a decision card carrying two witnesses (DOM and SAM) and its real cost. The user signs it, the train leaves, the action runs once on sandbox data, and the drawn rail stays as a live "Rail" scene.

### Flow (first act, one state model)
`key` (guided Meta key paste + live probe) -> `look` (drop a screenshot or use an open tab; Muse vision pre-fills apps and chore guesses; consent line) -> `interview` (frontier rounds, each question with a recommended answer; coverage meter over the 5 slots) -> `map` (ranked playbook candidates with economics; pick) -> `review` (commit boundary: what the test run will do, on which sandbox, which actions are gated, est. cost - rendered from the same assembly the run uses) -> `rehearse` (sandbox tab opens; live Muse turn, or recorded fallback after 20 s; card with witnesses; optional "pull the plug" Llama drill) -> `signed` (lever pulled; execute on sandbox; ledger row; train leaves) -> `later` (Voice, Face, connect a real app; finish -> `settings.onboarded=true`, land on the Rail root).
The rail (Yard, Interlocking, Line, Timetable, Train Register, Test Track) is visible beside every step and fills from the same state.

### Data & API
Routes (daemon, all `X-Athena-Token`):
- `POST /onboarding/look` body `{png_b64, consent: true}` -> `{apps: [{name, url?, confidence}], chores: [{text, confidence}]}`
- `POST /onboarding/interview` body `{answers: Answer[], round: n}` -> `{questions: [{id, slot, text, recommended, options?}], coverage: {apps, chore, hand, worth, never}, gate_open: bool}`
- `POST /onboarding/map` body `{answers}` -> `{candidates: [{playbook_id, title, fit, annual_value_usd, gates: [{action, label}]}]}`
- `POST /onboarding/sandbox` body `{playbook_id, answers}` -> `{sandbox_id, origin, url}`; `GET /sandbox/<sandbox_id>/` serves the page; `DELETE /onboarding/sandbox/<sandbox_id>`
- `POST /witness` body `{card_id, png_b64, box: [x,y,w,h], label}` -> `{iou, agree, source: "meta"|"modal"|"none", ms}`
- existing `POST /run` gains optional `surface: "rehearsal"` and `replay_after_s: 20`; run events gain `recorded: {date}` when replayed and `diverted: {from, to}` on a breaker trip.
- existing `POST /decisions/<id>` is unchanged (the lever).
Types: `Answer {question_id, slot, value, source: "recommended"|"edited"|"skipped"}`; `Slot = "apps"|"chore"|"hand"|"worth"|"never"`; `OnboardingStep = "key"|"look"|"interview"|"map"|"review"|"rehearse"|"signed"|"later"`; `RailBuild = "ghost"|"laid"|"beat"`; `RailSection = "yard"|"interlocking"|"line"|"timetable"|"register"|"test"`.
Persistence: `settings` key `onboarding.v1` = `{v: 1, step, answers, coverage, playbook_id?, sandbox_id?, card_id?, signed_at?}`; on finish the snapshot is reaped and a `projects` row `{id, playbook_id, title, created_at, source: "onboarding"}` is written. `settings.railBuild` while prototyping. Key file `meta-key.json` in app data (Rust only).
Ledger: schema unchanged; `surface` values `onboarding` and `rehearsal` added; `cost_estimated=True` for Meta prices.
Absent values: omit the key when unknown; `cost_usd: null` means unpriced (the existing ADR 0122 meaning); witness unavailable is `source: "none"` with no `iou` key, rendered "one witness".

### UX/UI spec
- First act: Blue Hour skin; the rail (selected renderer) on the left 60%, the step plate on the right 40%; at 390 wide the step plate stacks over a compact rail strip. The intro hands over control in <= 4 s; reduced motion = no train travel, lamps switch.
- States per step: key (empty / probing / ok with latency / invalid with Meta-page remedy / network down), look (empty / consent / reading / guesses / skipped), interview (round n, open count, coverage meter; Muse slow -> "still thinking" after 3 s; error -> retry or answer without suggestions), map (candidates / no good fit -> 3 closest + catalogue), review (assembled payload; gated actions in plain words), rehearse (sandbox opening / Muse turn streaming / recorded-fallback plate / card waiting with witness lamps / diverted to Llama), signed (stamp "signed, ran once on sandbox data"; train leaves).
- Primitives from components/CATALOG.md (Button, Badge, StatusDot, Facts, ProblemNote, EmptyState); new primitives stay local until a second caller.
- Rail root: L0 six brass plates, L1 section, L2 item dossier; key plan, breadcrumb, Escape, `/` find; 12 px floor; places never move.

### Strings
Inline English per repo convention; plain words for non-developers (no "token", "OP", "manifest" on screen). No translation ritual.

### Non-goals
Hosted web onboarding; a trial relay or shipped demo key as the product path; Muse-authored worlds; the rail as home; the OS keychain; Voice/Face in the critical path; running the test run against a user's real app; a Gauntlet run inside onboarding (the Test Track shows the baseline and the planned Muse re-run).

### Risks
- Meta API shape unknown (OpenAI-compatible? Llama under the same key? SAM offered?) -> WP1 day-1 probe; adapters behind `ModelFn`/`Witness`; Baseten and Modal fallbacks named.
- A non-developer may not have a Meta developer account -> the key step's remedy copy; the demo film uses mira's prepared account.
- capture.rs is Windows-only -> macOS/Linux show "one witness" honestly.
- Interview latency stacks per round -> frontier batching keeps it to 2-3 rounds; "still thinking" plate at 3 s.
- Bridge injection on a loopback sandbox origin is new -> the WP2/WP3 seam is smoke-tested on the built app before ship.
- Blue Hour tokens vs the style guards (`--accent` not ink, motion pairs) -> scoped skin, guards run in WP3.
- Recording 10-15 Muse runs costs money and time -> record after WP1 lands; hero chore first.
